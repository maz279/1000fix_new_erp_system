## 3. Findings

### MD-01 — The §1 distribution table disagreed with its own register in 20 of 21 categories

**Severity: CRITICAL · Status: FIXED · Owner: Programme Content Lead**

**What was found.** The Master Index §1 priority-distribution table and the §4 register rows were
extracted independently and compared. **Twenty of twenty-one categories disagreed.** Only `VB`
matched — because it was reconciled during `AUDIT-002`.

| | Stated in §1 | Counted from §4 rows | Difference |
|---|---:|---:|---:|
| `P0` blocking | 96 | **105** | +9 |
| `P1` must-have | 173 | **190** | +17 |
| `P2` important | 129 | **142** | +13 |
| `P3` desirable | **54** | **15** | **−39** |
| Total | 452 | 452 | 0 |

Per-category examples of the divergence:

| Category | Stated `P0/P1/P2/P3` | Actual | |
|---|---|---|---|
| `MD` | 26/15/6/1 | **29/13/6/0** | Drove this audit |
| `DT` | 14/18/10/2 | **10/22/12/0** | |
| `SP` | 6/17/10/1 | **2/21/11/0** | |
| `HC` | 2/8/8/2 | **0/6/11/3** | |
| `EO` | 1/5/6/2 | **0/3/8/3** | |

**Why it matters.** `P0` is defined as *blocking — no wave can go live without them*. The
programme was told there were **96 blocking files**; there are **105**. Wave planning, the
`CG-014` P-02 gate metric (*100% of `P0` content complete at gate minus four weeks*) and the
Phase 0/1 roadmap in §6 were all sized against the wrong number.

The `P3` gap is the largest in relative terms: 54 stated against 15 actual. Fifty-four
"desirable" files sounded like a comfortable deferral buffer. There are fifteen.

**Why it happened — reported openly.** I wrote the §1 summary table when the register was
designed, **before authoring the 452 individual rows**, and then never reconciled the two. The
category totals were correct because I counted those; the priority breakdown was a projection I
never went back and checked.

This is precisely the defect class of `AUDIT-001` **AF-02** (README 76% versus FOLDER_STRUCTURE
28%) and **AF-03** (README declaring written modules unwritten). Both were caused by a summary
figure written from intention rather than from enumeration.

**It is also a breach of a rule I wrote.** `CP-11` and `CM-R2` state that figures are generated,
never projected, and `CG-001` §3.4 specifies the exact commands. I did not run them on my own
summary table.

**Fixed.** The §1 distribution table and the four priority-summary lines were regenerated by
direct extraction from the 452 register rows, and now reconcile exactly. The extraction is
scripted and repeatable.

**Prevention.** Recommendation **R-01** below adds this reconciliation to the automated check
set so it runs per commit rather than per audit — which is what `AUDIT-002` recommendation R-07
already proposed and which had not yet been implemented when this defect was introduced.

### MD-02 — `MD-043` payroll depends on `MD-035`, which is not loaded until a different wave

**Severity: High · Status: OPEN · Owner: MDM Lead with CFO**

**What was found.** `MD-043` Payroll Element and Statutory Deduction Register is `P0`, **wave
W5**. Its dependency table names `MD-035` Chart of Accounts (`P0`, **W1**) as a hard prerequisite,
which is satisfied.

But the reverse case exists and is not satisfied: **`MD-038` Payment Method, Term and Bank Master
is `P0` at W3, and `M20` accounts receivable and `M50` treasury are W1–W3 modules that need it.**
Meanwhile `MD-037` tax codes (W1) is a hard prerequisite of `DT-010` Mushak 6.3, which is a `P0`
W1 document.

Tracing the wave assignments across the 48 files against the load tiers declared in `MD-048`
§2.1 shows **three datasets whose wave is later than the earliest wave that consumes them**:

| Dataset | Wave | Consumed by | Consumer wave |
|---|:--:|---|:--:|
| `MD-038` Payment methods | W3 | `M20` receivables, `UI-039` payment copy | W1–W2 |
| `MD-011` Certification register | W2 | `BRU-SRM-09` dispatch gate (`M02`) | W1 |
| `MD-043` Payroll elements | W5 | `M56` payroll parallel run | W5 — **satisfied** |

**Why it matters.** A `P0` dataset that arrives after the module consuming it means the module
goes live with a hard business rule it cannot evaluate. `BRU-SRM-09` — no uncertified technician
on brand warranty work — is the clearest case: `M02` dispatch is W1, `MD-011` is W2.

**Not fixed.** Changing a wave assignment is a roadmap decision (`06-01`), not a content one.
The three cases are raised for the MDM Lead and PMO to either re-wave the dataset or accept a
documented interim control.

### MD-03 — Three Class A datasets cannot be activated, and this blocks W1 finance

**Severity: Medium · Status: OPEN — correctly marked, escalation required**

`MD-035` Chart of Accounts, `MD-037` Tax/VAT/Mushak mapping and `MD-043` Payroll elements are
Class **A** statutory. Gate **G6** external verification is mandatory and unwaivable (`WV-02`),
with a 15-working-day service level driven by external adviser availability (`CG-007` §6).

All three correctly load their sample rows `active = FALSE` pending verification, and each
states this in its Definition of Done. **That is the right handling.** The finding is the
consequence:

> **No transaction can post, no invoice can be issued and no payroll can run until an external
> tax adviser has verified three datasets.** `MD-035` is the first configuration object of the
> finance go-live.

`CG-007` §10 already records that G5 and G6 capacity — not drafting capacity — determines when
statutory content can ship. This is the first concrete instance: **W1 finance go-live has a hard
dependency on an external adviser engagement that is not yet contracted.**

**Action:** contract the adviser engagement now, per `AUDIT-002` recommendation R-03's pattern.
Raised as recommendation **R-02**.

### MD-04 — A non-ASCII character entered a generated file

**Severity: Medium · Status: FIXED**

`MD-042` §6 contained the string `field测 test` — a stray CJK character introduced during
generation.

**Why it matters beyond the typo.** `CG-005` `ID-08` bans non-ASCII in paths; it does not ban it
in content, and Bengali content is deliberately non-ASCII. So no automated check caught it. It
is a reminder that generated content needs the same review as authored content — `CG-002`
`CO-09` makes a 1000FiX function Accountable for vendor-produced content for the same reason.

**Fixed.** Corrected to `field test`. A lint rule for unexpected script ranges outside declared
Bengali content is proposed as recommendation **R-04**.

### MD-05 — `MD-013`, `MD-048` and `MD-001` are Class E but carry operational data

**Severity: Low · Status: ACCEPTED, documented**

`CG-002` §4.1 allocates `MD` three Class **E** internal-governance files. I assigned them to
`MD-001` (governance charter), `MD-013` (party master **standard**) and `MD-048` (load index).

`MD-013` is arguably Class **C** — the party model governs 300,000+ records and a defect in the
matching rules is an operational failure, not a documentation one.

**Accepted rather than changed**, because moving it to C would make the class counts diverge from
`CG-002` §4.1, and the class allocation there was ratified first. The tension is recorded so a
future reviewer does not read it as an error. If `CG-002` is revised, `MD-013` should move to C
and a different file take the E slot.

## 5. Observations

### 5.1 The governance set caught its own author

`CG-002`, `CG-005` and `CG-010` were written before this category. Every conformance check
against them passed on the first run: class allocation, bilingual split, ID contiguity, template
declaration, subfolder placement. **The controls work.**

What they did not catch is MD-01 — because no control existed for *the register's own summary
table*. The rule existed (`CP-11`, `CM-R2`); the automation did not.

### 5.2 The same defect, three audits running

| Audit | Finding | Shape |
|---|---|---|
| `AUDIT-001` | AF-02, AF-03 | A summary figure written from intention, not enumeration |
| `AUDIT-002` | VB-02 | `CR-13` cited before it was created |
| `AUDIT-003` | **MD-01** | A summary table written before the rows it summarises |

Three audits, three instances, three different documents. The rule is not the problem — the rule
is written down in four places. **The gap is that enumeration is a recommended practice rather
than an executed check.** R-01 closes it for the content set.

### 5.3 What this category exposes about the programme

Authoring 48 master-data specifications surfaced dependencies that no single module file shows:

- **Three `P0` datasets arrive after the modules that need them** (MD-02)
- **W1 finance go-live depends on an uncontracted external adviser** (MD-03)
- `MD-009` carries the unresolved `00-07` H2-07 role registration finding — **11 of 49 roles are
  unregistered or undefined**, and access control cannot be configured against them
- `MD-017` is where the unverified "17+ brands" figure (`00-07` H2-12, `CR-05`) must finally be
  verified against executed agreements
- `MD-034` is blocked by the `VB-010` §13 "Privileged Program" naming decision — and once it
  loads, the rename becomes a migration

None of these is a content defect. All five are programme risks that only became visible when
somebody wrote down what the data actually has to contain.
