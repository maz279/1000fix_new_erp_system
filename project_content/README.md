**452 content files · 21 categories · 2 languages · 9 delivery waves**

## What this repository is

The 1000FiX ERP programme has 67 module specifications and 12 portal specifications in
[`../1000fix_ERP_Module/`](../1000fix_ERP_Module/). Those documents say **what the system must
do**.

This repository holds **what must be written, seeded, translated, approved and maintained so
that the system can be operated** — by 500+ employees across 51+ branches, for 250,000+
customers a month, with 17+ brand partners, 500–2,000 marketplace sellers and 500–2,000
corporate users, in Bengali and English.

Master data, UI copy, notification templates, statutory documents, SOPs, training, help
content, legal terms, migration mappings, test scripts, runbooks and registers.

## Before you write anything

1. **Find your file in the Master Index.** If it is not registered, register it first — rule
   `CM-R1`. Register-first, always.
2. **Use the template** from `_templates/` for your content type — principle `CP-09`.
3. **Fill the front matter completely**, including `purpose:` (why the file exists) and
   `traces_to:` (the module, portal or specification that requires it) — principles `CP-03`
   and `CP-04`.
4. **Name the source** for every factual, statutory, pricing or capability claim, with a
   verification date — rule `CM-R8`.
5. **Check the bilingual flag.** If your file is bilingual it is not `Approved` until the
   Bengali counterpart has passed in-context linguistic sign-off — rule `CM-R6`.
6. **Pass the Definition of Done** in `CG-008` before setting status to `Approved`.

## Naming

```
<CODE>-<nnn>_<Descriptive_Name_In_Title_Case_With_Underscores>.md
```

Bengali counterparts take a `_BN` suffix on the same stem. Data files share the stem of their
governing markdown specification. IDs are permanent and never reused — principle `CP-02`.

**No spaces or ampersands in any folder or file name.** See audit finding **AF-12**.

## Relationship to the corporate website content set

The website programme maintains a separate set of 427 registered files. **The two are
deliberately separate and must not be merged** — different audiences, lifecycles, priority
scales and approval authorities. Four defined interfaces exist between them; all four are owned
on the ERP side. See Master Index §11.

⚠ The website set uses a `P1`–`P4` priority scale. This set uses `P0`–`P3`. The letters look
identical and mean different things — audit finding **AF-11**.
