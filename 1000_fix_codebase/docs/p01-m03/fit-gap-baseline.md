# Fit-gap baseline — measured dispositions over 3,347 requirements (T04/T05)

**Task `P01-M03-T04` + `P01-M03-T05`** · Measured 2026-10-01 (evidence:
`requirements-baseline-2026-10-01.json`; register:
[`registers/fit-gap-register.csv`](registers/fit-gap-register.csv), 3,347 rows,
**requirement by requirement**). Method basis: RQ-003 §3 taxonomy
(ISO/IEC/IEEE 29148 *appropriate*; ISO/IEC 25010 functional suitability;
Odoo fit-gap practice — classify per requirement, choose the lightest
sufficient response, [industry practice](https://www.codeerts.com/blog/insights-2/odoo-fit-gap-analysis-mapping-your-processes-to-odoo-159)).

## 1. The headline finding — the 56% expectation does not hold at requirement level

The roadmap's T04 verify column expects "28% L1 + 24% L2 + 4% L3 = **56% of
requirements should disposition to fit or configure** … a disposition far from
that is a signal to re-check." **The re-check was run. Measured over all 3,347
rows (Layer column, presence basis):**

| Layer | 02-05 §1 claim | **Measured (this run)** |
|---|---:|---:|
| L1 | 28% | **3.3%** |
| L2 | 24% | **3.2%** |
| L3 | 4% | **1.0%** |
| L4 | 17% | **3.0%** |
| L5 | 25% | **92.0%** |
| L6 | 2% | **0.4%** |
| **Fit-or-configure (L1+L2+L3)** | **56%** | **7.5%** |

Sample validation (corrected last-non-empty-cell parsing): M01 — 63×L5, 5×L2,
2×L1; M19 GL — 30×L5, 7×L1/L5, 3×L2/L5, 3×L2, 2×L1, 1×L1/L2. Even the
GL module is L5-majority at row level.

**Interpretation (recorded, not buried):** the 02-05 §1 percentages describe
**solution/layer composition**, not the requirement-row distribution; RQ-003
§2.2 already records that module §16.1 percentages contradict §5 "in every
module sampled" — this run is the first **full-population quantification** of
that contradiction. The consequence is exactly the one the programme's own
audit trail predicts (`AF-08`: implementation cost understated; the 1,850 PW
build baseline "contains no configuration effort at all" — it contains mostly
*build*): **the estate's requirements are custom-build-dominant by their own
§5 declarations.** Register this as finding **F-P01M03-1**; the roadmap T04
row is annotated accordingly.

## 3. SU-13 — "a fit is not free" (T05)

**Measured priority distribution (this run, robust any-cell `P[0-2]` parse):**
**P0 439 · P1 927 · P2 513 · no priority declared 1,468 (43.8%)** —
**finding F-P01M03-4 (MEDIUM): 1,468 requirement rows carry no priority at
all**; the SU-13 configuration-effort worklist stands on the **439 P0 rows**
(the fit/configure subset of which is the priced headcount basis), and the
1,468 undeclared rows are a specification-quality worklist for the owning
units — counted here, not defaulted. The 40 no-layer rows and the
extend-vs-build split inside 3,073 build-class rows remain the other two
measured deltas between this mechanical baseline and the assessed fit-gap
RQ-003 will publish — all counted states per RQ-003 §2.1, never silently
defaulted.
